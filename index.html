SOHOWALL

A Multi-Layered Intelligent Firewall Architecture for SOHO Networks

Small office and home office networks face the same threats as enterprises, without the expertise, budget or hardware that enterprise defences assume. SOHOWALL combines four layers: threat-intelligence scoring with an ML fallback, TinyML anomaly detection, privacy-preserving data loss prevention and a natural-language firewall. Together they protect the network, enforce policy safely and keep an audit trail.

What is SOHOWALL?

Four layers, one firewall

Four properties a SOHO network needs, each provided by one layer.

Predictive

Scores network indicators against threat-intelligence feeds, with an ML fallback for hosts no feed has seen.

M1

Adaptive

A TinyML autoencoder learns normal traffic patterns and scores deviations from them.

M2

Private

Detects personal data and keeps each user's risk score under fully homomorphic encryption.

M3

Accessible

Lets non-experts manage the firewall in plain English instead of rule syntax.

M4
Built for SOHO

Designed for small networks

Design choices across the four modules that suit small office and home office networks.

Lightweight

A TinyML autoencoder for anomaly detection, and a Flan-T5 rule generator fine-tuned with LoRA (0.45% of parameters trainable).

  • M2
  • M4

Privacy-preserving

Each user's DLP risk score is kept under fully homomorphic encryption (Microsoft SEAL, BFV).

  • M3

Fail-safe

An ML-ensemble fallback scores hosts no feed lists, a regex fallback backs up rule generation, and M4's external API fails closed.

  • M1
  • M4

Accountable

Every block and unblock is logged in M4's SQLite audit trail and can be reversed in one step; M3 logs events for admin monitoring.

  • M1
  • M3
  • M4
How it works

From capture to audit

The enforcement path, tagged with the modules that take part. M2 scores traffic features for M1's dashboard and M3 runs as a separate DLP layer; only M4 writes firewall rules.

  1. 01

    Capture

    Scapy captures DNS, TLS SNI and TCP SYN/SYN-ACK/FIN metadata.

    • M1
  2. 02

    Score

    Indicators get an ATT&CK-derived score with feed corroboration and freshness; an ML ensemble scores hosts no feed lists.

    • M1
  3. 03

    Request

    A block or unblock request goes to M4's token-protected API over HTTP.

    • M1
    • M4
  4. 04

    Enforce

    M4 writes iptables rules and /etc/hosts sinkhole entries.

    • M4
  5. 05

    Audit

    Every block and unblock is logged in M4's SQLite audit trail.

    • M4
Detection layers beside the enforcement path
M2

Anomaly detection

Receives windowed statistical and FFT features from M1 over HTTP and returns an anomaly score, shown on M1's CTI dashboard. Runs as a standalone TinyML microservice (monitor.py).

M3

Data loss prevention

Transformer models detect PII and its type, each user's risk score is kept under fully homomorphic encryption (Microsoft SEAL), and a Flask app handles logging and admin monitoring.
