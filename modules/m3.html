Data Loss Prevention

PII detection with FHE-protected risk scoring

Pathiranage M.D. · IT22100252 · Member

  1. Overview
  2. Problem
  3. Features
  4. How it works inside
  5. Tech stack
  6. Connections
Overview

M3 detects personal data with transformer models and keeps each user's risk score under fully homomorphic encryption (Microsoft SEAL, BFV), with a Flask app for logging and admin monitoring.

Problem

Research question

A conventional firewall controls addresses, ports and known indicators, but a policy such as “do not send a personal phone number or identity document” needs content-level interpretation, and copying text or capturing a screen can precede a leak without any outgoing packet. M3 builds a DLP prototype that separates sensitive from ordinary material in selected workflows, keeps explainable event records and limits the privacy risk of monitoring itself.

  1. How reliably can the token-classification model identify the PII classes relevant to the SOHO DLP policy?
  2. Does application-mediated text inspection stop outgoing e-mail that contains designated sensitive content while allowing benign e-mail?
  3. Can clipboard and screenshot signals be recorded and attributed accurately without collecting excessive sensitive data?
  4. Does homomorphic accumulation produce exact risk totals while keeping the ciphertext unreadable in the database?
  5. What performance and operational trade-offs arise compared with rule-only and non-encrypted baselines?
Features

What it does

  1. 01

    PII detection

    A transformer model detects personally identifiable information.

  2. 02

    PII type identification

    A second transformer model identifies the type of PII found.

  3. 03

    FHE risk scoring

    Risk is accumulated under fully homomorphic encryption through a node-seal REST API.

  4. 04

    Logging and admin monitoring

    A Flask app logs events and gives administrators a monitoring dashboard.

How it works inside

Pipeline

  1. 01

    Detect

    A transformer model detects PII.

  2. 02

    Identify

    A second transformer model identifies the PII type.

  3. 03

    Score

    The user's risk score is updated under fully homomorphic encryption (Microsoft SEAL, node-seal).

  4. 04

    Monitor

    A Flask app handles logging and admin monitoring.

Tech stack

Technologies

Encryption
  • Fully Homomorphic Encryption
  • Microsoft SEAL
  • node-seal
  • BFV
Models
  • Hugging Face Transformers
  • BERT token classification
  • PII detection
  • PII type identification
  • face_recognition
Application
  • Node.js / Express REST API
  • Flask
  • MySQL
  • Electron desktop apps
Versions
  • node-seal 5.1
  • Express 4.18
  • Electron 25
Connections

How it connects

Inputs
User activity reported by the client engine on each endpoint: clipboard content, screenshots, outgoing e-mail and attachments, keyboard input and login attempts (with face-recognition login).
Outputs
PII findings and an encrypted risk score.
Interfaces
The node-seal FHE REST API and the Flask logging / admin app.
